# World of Warcraft Addon Development Guidelines

## API Ground Truth
- NEVER search the web for World of Warcraft API signatures.
- **Primary source (if present): `./.wow-api-cache/forever/`**, generated from the live Forever client.
  - `REPORT.md` lists `C_*` functions/events that exist only in Forever, and ones in Ketho's annotations that do NOT exist in Forever (never use those).
  - `Annotations/Systems/`, `Enum.lua`, `Event.lua`, `Widgets.lua`, `Undocumented.lua`, `api.json` (raw).
  - Regenerate: enable addon `ForeverAPIDump`, in game `/apidump` then `/reload`, then `python tools/forever-api/convert.py`. Suggest a regen to the user after a game patch (compare build in `REPORT.md` with `.flavor.info`/client).
- Secondary source: Ketho's annotations (below). Use them for documentation text and for anything the Forever dump doesn't describe.
- All valid WoW Global APIs, frames, widgets, widget methods, and events are explicitly defined as EmmyLua types within the local folder: `./.wow-api-cache/vscode-wow-api/Annotations/`
  - `Core/Blizzard_APIDocumentationGenerated/` – `C_*` namespaces and global API functions
  - `Core/Widget/` – frame/widget types and their methods (`Frame`, `FontString`, `Texture`, `Button`, animations…)
  - `Core/ScriptObject/` – script handlers (`OnEvent`, `OnUpdate`, `OnClick`…)
  - `Core/Data/Event.lua`, `Enum.lua`, `CVar.lua` – events + payloads, `Enum.*` tables, CVars
  - `Core/Data/Classic.lua` – Classic-only API variants (differ from Retail signatures)
  - `Core/FrameXML/` – Blizzard Lua mixins/utils (`Mixin`, `CreateFromMixins`, `C_Timer`-style helpers)
  - `Core/Lua/` – what the Lua 5.1 sandbox allows (`os.lua`, `string.lua`, `table.lua`, `bit.lua`…)
  - `Core/Libraries/` – Ace3, LibStub, LibSharedMedia, LibDBIcon, etc.
- Before writing any frame creation methods, text strings, or event loops, read the corresponding definition inside `./.wow-api-cache/` to ensure accurate arguments and return variables (use Grep, e.g. `function C_Item.GetItemInfo(` or the event name).
- If an API is NOT in the annotations, do not invent it. Check whether installed addons in `Interface/AddOns/` use it (real-world evidence for this client), otherwise ask the user.

## Target Client: WoW Forever
- Product flavor `wowf` (see `.flavor.info`), TOC `## Interface: 16001`. Forever-specific TOC files may use the `_Camelot` suffix.
- The client is Retail-engine based (installed addons also list 120xxx interface versions), so the Retail (Mainline) annotations are the default reference. Annotations target Retail and may not match Forever exactly; verify against installed Forever addons when unsure.

## Coding Conventions
- Target Environment: WoW Forever / Lua 5.1 Sandbox
- Avoid Lua functions removed by the WoW sandbox: `io.*`, `os.clock`, `os.execute`, `os.exit`, `os.getenv`, `os.remove`, `os.rename`, `os.tmpname`, `loadfile`, `dofile`, `require`. `os.time`/`os.date`/`os.difftime` are available, but prefer the globals `time()`, `date()`, `GetTime()`.
- Use Blizzard's `CreateFrame("Frame", nil, UIParent)` structure for generating UI elements.

## Git: SavedVariables
- Whenever `git status` shows new or modified files under `WTF/**/SavedVariables/` (they change when the game is opened/closed), commit them **as their own separate commit** (only SavedVariables paths, nothing else), e.g. `git add -A -- ':(glob)WTF/**/SavedVariables/**' && git commit -m "Update SavedVariables" -- ':(glob)WTF/**/SavedVariables/**'` (plain `WTF/**/...` pathspecs don't match without `:(glob)`). This standing instruction allows that commit without asking first.
- WTF config/cache files (`config-cache.wtf`, `*-cache.txt`, `cache.md5`, `*.old`, `layout-local.txt`, …) are git-ignored; do not commit them.
